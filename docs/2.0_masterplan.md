🗺️ Master Roadmap: PD Noise Generator v2.0
Theme: From "Random Noise" to "Generative Incident Narratives"

1. Product Vision
Version 1.0 was about generating volume (traffic). Version 2.0 is about generating realism and narrative. The goal is to move away from static JSON templates and hardcoded strings, replacing them with AI-generated content that tells a coherent story of a system failure across the entire DevOps ecosystem (PagerDuty, Slack, Jira, Observability).

2. Core Pillars
Generative Payloads (AI): No more repeated static alerts. Every stack trace, error message, and "War Room" chat is unique, generated by an LLM to match a specific failure scenario (e.g., "Redis Latency" vs. "Payment Gateway 500s").

Ecosystem Simulation: Incidents don't exist in a vacuum. The generator will now optionally spawn "shadow" artifacts in Slack (simulated chat) and Jira (tickets) to mimic a real incident response process.

Director Mode: A new "Live Operations" dashboard allowing a presenter to manually inject events, comments, or status updates in real-time during a demo.

3. Architecture Changes
Backend (/server)
New Service: AiService

Interface with Google Gemini API.

Responsibilities:

generateAlertPayload(scenario): Creates unique JSON blobs with realistic stack traces.

generateResponderChatter(context, sentiment): Creates "human" comments for the incident timeline (e.g., "I'm checking the logs now...").

generatePostMortem(incidentId): (Future) Drafts a resolution note.

New Service: IntegrationService

Responsibilities:

Handling webhooks/API calls to external tools (Slack Webhooks, Jira API).

Maintaining "Fake User" mappings (mapping a PagerDuty simulated user to a Slack username).

Refactored: GeneratorEngine

Move away from Math.random() selection of templates.

Implement a NarrativeContext object that follows an incident lifecycle, ensuring that subsequent alerts relate to the first one (e.g., "High CPU" follows "Memory Leak").

Frontend (/client)
New View: DirectorDashboard

A grid-based "Soundboard" UI.

Buttons for "Trigger Major Incident", "Inject Comment", "Resolve All".

Live feed of the "Narrative" (what the AI is currently simulating).

New Settings Page: Integrations

Input fields for Gemini API Key, Slack Webhook URL, Jira Credentials.

Database (Prisma Schema)
New Model: NarrativeTemplate

Stores "Prompts" rather than JSON. (e.g., "Scenario: Database deadlock on Black Friday").

New Model: IntegrationConfig

Stores encrypted credentials for 3rd party tools.

4. Implementation Phases
We will execute this roadmap in 4 Distinct Phases. We will not start a new phase until the previous one is fully tested and merged.

Phase 1: The AI Engine (Foundation)
Goal: Replace static JSON templates with Gemini-generated content.

Key Tasks:

Setup AiService wrapper for Gemini API in Node.js.

Create prompt templates for "Java Stack Trace", "Python Error", and "Go Panic".

Refactor the existing simulators/incident.ts (or equivalent) to call AiService instead of loading local JSON files.

Add "War Room Chatter" generation (AI-generated comments added to the PagerDuty incident).

Phase 2: "Director Mode" (User Experience)
Goal: Give the user real-time control over the simulation.

Key Tasks:

Build the DirectorDashboard UI in React.

Create WebSocket endpoints in server to receive "Instant Action" commands.

Implement "One-Click Scenarios" (e.g., clicking "DDoS Attack" instantly queues 50 related alerts).

Phase 3: The Ecosystem (Integrations)
Goal: Expand noise beyond PagerDuty.

Key Tasks:

Implement IntegrationService for Slack Incoming Webhooks.

Update the simulation loop to post to Slack whenever a P1 incident is created.

(Optional) Simple Jira ticket creation via REST API.

Phase 4: Polish & Persistence
Goal: Save scenarios and historical replay.

Key Tasks:

"Replay" mode: Upload a CSV of past incidents to replay them.

Save successful AI-generated scenarios as "Favorites" to the database.
